## 本页目标

树莓派上做视觉，第一件事是**量化**：一帧到底花多少毫秒？本页在画面里直接打出 `SIZE` 和 `PROCESS`，你改一个参数就能看到耗时的变化，不用靠感觉判断"是不是卡"。

## 前置条件

- 完成 8.1
- 同目录有 `camera.py`、`target_observation.py`（6.6 / 4.6 的颜色观测）

## 动手步骤

**1. 新建 `47_measure_opencv.py`**

**2. 写入核心代码**

```python
import time
import cv2
from camera import Camera, log_message
from target_observation import draw_target_marks, find_target

PROCESS_WIDTH = 640       # 处理宽度，越小越快、细节越少


def resize_image(image):
    """按处理宽度等比例缩小，保持宽高比不变形。"""
    if image.shape[1] <= PROCESS_WIDTH:
        return image
    scale = PROCESS_WIDTH / image.shape[1]
    image_height = round(image.shape[0] * scale)
    return cv2.resize(image, (PROCESS_WIDTH, image_height))


def run(camera):
    last_image = None
    last_state = None

    while True:
        if cv2.waitKey(20) == 27:
            return

        image = camera.latest()
        if image is None or image is last_image:
            continue                    # 只测新帧，否则测的是重复处理的耗时
        last_image = image

        # 计时只包住真正要做的事：缩图 + 观测 + 绘制
        start_time = time.monotonic()
        image = resize_image(image)
        target_data = find_target(image)
        marked_image = draw_target_marks(image, target_data)
        processing_time = (time.monotonic() - start_time) * 1000

        text = f"SIZE {image.shape[1]}x{image.shape[0]}  PROCESS {processing_time:.0f} ms"
        cv2.putText(marked_image, text,
                    (20, marked_image.shape[0] - 20),
                    cv2.FONT_HERSHEY_SIMPLEX, 0.55, (0, 176, 255), 2)
        cv2.imshow("OpenCV performance - Esc to close", marked_image)

        if target_data["state"] != last_state:
            log_message("INFO", "opencv",
                        f"状态: {target_data['state']}  处理耗时: {processing_time:.0f} ms")
            last_state = target_data["state"]


def main():
    try:
        with Camera() as camera:
            run(camera)
    except KeyboardInterrupt:
        print("结果: Ctrl+C 主动结束")
    except (OSError, ValueError, cv2.error) as exc:
        log_message("ERROR", "camera", str(exc))
    finally:
        cv2.destroyAllWindows()


if __name__ == "__main__":
    main()
```

**3. 运行，记下 `PROCESS` 数值；把 `PROCESS_WIDTH` 改成 480、320 再各记一次**

## 参数说明

| 参数 | 类型 | 默认值或范围 | 说明 |
| --- | --- | --- | --- |
| `PROCESS_WIDTH` | int | 320 / 480 / 640 | 处理宽度。**这是唯一需要调的旋钮** |
| 计时范围 | — | 缩图+观测+绘制 | 只测业务流程，不含 `latest()` 取图 |
| `last_image` 去重 | — | — | 不去重会把"处理同一帧"算进耗时，结果偏低 |

## 参考数值（树莓派 4B，仅作量级参考）

| 处理宽度 | 单帧耗时 | 可用帧率 |
| --- | --- | --- |
| 640 | 30～60 ms | 15～30 FPS |
| 480 | 20～35 ms | 25～45 FPS |
| 320 | 10～20 ms | 50+ FPS（受摄像头出帧限制） |

树莓派 Zero / 3B 会慢 2～3 倍。**颜色掩膜本身很便宜**，真正贵的是缩图和绘制；如果你的耗时远高于上表，先查是不是在做全尺寸 `imshow`。

## 一个容易忽略的副作用

缩图会改变**像素面积**，所以 `MIN_AREA` 之类的面积阈值必须跟着调。从 640 缩到 320，面积变成原来的 **1/4**，原来的 `MIN_AREA=500` 在 320 上相当于原来的 2000 —— 目标可能直接被过滤掉。

| 处理宽度 | 面积阈值应乘的系数 |
| --- | --- |
| 640 | 1.0（基准） |
| 480 | ≈ 0.56 |
| 320 | ≈ 0.25 |

## 预期效果与排查

画面底部显示 `SIZE 640x480  PROCESS 42 ms`；切 320 后耗时明显下降，但小目标可能识别不到（正常）。

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 耗时波动很大 | 后台在重连/系统调度 | 多次采样取中位数，别只看一瞬间 |
| 耗时异常低（<5 ms） | 没做 `last_image` 去重 | 加去重，只测新帧 |
| 缩图后目标消失 | 面积阈值随缩图变小 | 按上表乘系数调整 `MIN_AREA` |
| 温度飙高 | 无散热持续跑 | 见 8.1，加散热片 |
