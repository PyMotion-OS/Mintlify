title: "5.2 常见问题"
---

本章按实际现象说明排查顺序。遇到执行器异常时，应先停止输出并确认现场安全，再继续检查程序和连接。

### 5.2.1 执行器没有动作

1. 是否连接外部电源，电压是否满足负载要求。
2. 是否进入 with `lite.control()`:。
3. 设备是否处于 ESTOP 或 FAULT。
4. 电机、PWM 端口和 TTL ID 是否与接线一致。
5. PWM/TTL 舵机声明的模式是否与实际模式一致。

### 5.2.2 数据不更新

- 传感器是否正确连接。
- valid 和 state 的值。
- age 是否超过设置的 `max_age`；两者单位均为秒。
- 实时会话是否持续调用 `session.data.read()`。
- `session.data.stats()`.dropped 是否增长。

### 5.2.3 Wi-Fi 可以发现但连接超时

先检查 Token、电脑当前 IP地址、配网页面的服务器地址，以及路由器或热点是否启用了访客/AP 隔离。多数 Windows 电脑不需要手动设置防火墙；只有设备和电脑已经确认能够互相访问、其他配置也正确，但 TCP 连接仍超时时，才检查防火墙或安全软件是否拦截 Python/SDK 接收设备发往电脑 TCP 8787端口的入站连接。可以仅在受信任的专用网络中允许对应程序或端口，不要直接关闭整个防火墙。

Wi-Fi 实时数据还要求电脑能够主动连接设备的 TCP 8787端口；该方向通常不需要 Windows 入站规则。手机热点息屏、访客/AP 隔离或节能设置也可能影响连接稳定性。

### 5.2.4 电机位置控制不准

检查编码器 ppr、gear_ratio、电机方向、供电、机械间隙和负载。执行位置运动前应在电机静止时调用 zero_position()。

### 5.2.5 里程计偏差较大

在实际地面重新测量轮子滚动直径和左右轮中心距离，并检查轮胎打滑、左右轮速度差和编码器反馈。

### 5.2.6 为什么指定 duration 后后面的代码晚执行

直流电机、连续旋转 PWM 舵机和速度模式 TTL 舵机的普通 API 在指定 duration 时，这期间是阻塞式的执行过程，会等待这段时间并完成停止后才返回。这适合简单教学和顺序动作。需要多个动作同时进行时，应使用批量 API、实时命令，或由应用程序自行调度。

### 5.2.7 为什么调用成功但 PWM 位置舵机没有准确到位

PWM 位置舵机接口没有实际角度反馈。调用成功只说明目标已接受。检查舵机供电、角度范围、舵臂是否受阻以及是否预留足够运动时间；需要角度反馈时应使用能够报告位置的 TTL 舵机。

### 5.2.8 为什么 replaced 不是 0

它表示尚未发送的旧实时目标被更新目标或停止操作替换，不是数据包丢失。少量替换，特别是结束前零目标紧接 stop()，通常属于正常现象。持续大量增加时，应降低提交频率。

### 5.2.9 为什么选择 high 仍达不到 20 Hz

high是最高档位，不保证所有设备都是 20 Hz。环境光、颜色、电源、雷达、TTL 状态和超声波有效测距都有各自速度限制；同时订阅较多来源时，实际速度也可能低于目标。

### 5.2.10 USB 与 Wi-Fi 应该怎么选

- USB：连接直接，适合首次使用、固定工位和排查问题；不要求 Wi-Fi 在线，但需要正确 Token。
- Wi-Fi：适合移动机器人和无线控制；除正确 Token 外，还需要网络互通与稳定供电。
- 两种连接使用相同的控制和读取 API。切换时修改 `transport`；Wi-Fi 还需正确的设备 ID、Token 和配网页面中的 SDK 服务地址。

无论使用哪种连接，实时控制都应设置有效期、检查数据新鲜度，并在退出时停止执行器。

### 5.2.11 USB 和 Wi-Fi 都偶发超时或中断

如果 USB、Wi-Fi、实时数据和配网热点同时出现不稳定，不要只排查电脑网络。供电不足或电池内阻过大可能让设备在电机启动、快速换向或舵机动作时瞬间掉压，表现为连接超时、数据中断、设备重启或配网热点没有出现。

按以下顺序检查：

1. 停止全部执行器，确认电池类型、额定电压和接线符合硬件要求。
2. 读取设备电源状态，并观察电机启动和换向时的最低电压。
3. 如果电压字段不可用，使用万用表直接测量设备供电端，不要只测空载电池电压。
4. 更换已充满且能够提供足够电流的电池，再分别验证 USB 和 Wi-Fi。
5. 供电恢复正常后仍有问题，再检查 USB 线、串口占用、Token、电脑 IP、防火墙和网络隔离。

板载电压用于运行状态监视，不能代替经过校准的测量仪表。执行器负载变化较大时，应重点观察动作瞬间的压降。

### 5.2.12 直流电机位置控制出现 encoder_stall 或 position_timeout

- **`encoder_stall`（编码器失速）**：电机已输出但编码器角度没有按预期变化，常见原因是堵转、负载过大、供电不足或电机/编码器接线错误。先检查电机与编码器接线及供电，再适当调大 `tolerance`，让目标角度在更大的允许误差内视为完成。
- **`position_timeout`（位置超时）**：表示未在 `timeout` 设置的秒数内到达目标并稳定。建议适当调大 `speed` 或 `timeout`；若反复超时，还应检查供电与机械负载。
